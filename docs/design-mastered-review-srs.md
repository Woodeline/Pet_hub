# design-mastered-review-srs —— 已掌握词库与记忆曲线（间隔重复）系统（2026-10-01）

## 需求与决策

为已掌握并背熟的单词建立独立词库（与生词词库区分管理），并为其配备记忆曲线
（间隔重复 / SRS）系统：依据每个单词的掌握程度自动安排复习时间与频率，帮助长期巩固。

核心决策：

- **掌握即入 SRS**：任何路径（气泡「记住了」/ 详情「记住了」）标记掌握的词，
  立即携带复习排期进入已掌握词库——不是"学完就扔"，而是进入长期巩固轨道。
- **复习是主动回忆，不是再认**：复习泡泡**隐藏翻译/释义**，只给单词 + 假名，
  用户自评「还记得 / 忘了」；答案可双击气泡进详情「偷看」，偷看不打断复习。
- **遗忘不是惩罚而是回炉**：「忘了」→ 词退回生词本重学（SRS 状态一并清除，
  再次掌握时从首轮重新爬梯）；复习泡泡超时 → 无痕顺延 1 小时，不算遗忘。
- **复习不受每日配额约束**：每日上限只管新词学习量；复习间隔是记忆效果的
  刚性约定，到期就复习（但遵守气泡的全部既有守卫：单飞 / 睡觉 / 最小间隔）。
- **阶梯制而非 SM-2 全量**：固定间隔阶梯 (1, 3, 7, 14, 30, 60, 120) 天，7 轮
  毕业约 8 个月。对桌面宠物场景，可预期性 > 个性化优化（用户看不到 ease 因子，
  只看得到"阶段 3/7 · 7 天后复习"）。

## 一、数据结构（mastered.json v2）

```jsonc
{
  "version": 2,
  "items": [
    {
      "id": "n5-0001",           // 必填 str（v1 既有）
      "level": "N5",             // 必填 str（v1 既有）
      "word": "食べる",           // 必填 str（v1 既有，词条冗余快照）
      "kana": "たべる",           // 必填 str（v1 既有）
      "translation": "吃",        // 必填 str（v1 既有）
      "mastered_at": "2026-10-01T12:00:00Z",  // 必填 str（v1 既有）
      "stage": 0,                // v2：下一轮复习的间隔下标（0 起；== 7 为毕业）
      "due_at": "2026-10-02T12:00:00Z",       // v2：下次复习到期时刻；""=未排期/已毕业
      "last_review_at": "2026-10-01T12:00:00Z",// v2：最近一次复习时间（掌握瞬间=mastered_at）
      "review_count": 0          // v2：已完成复习轮数（不含掌握本身）
    }
  ]
}
```

- `REVIEW_INTERVALS_DAYS = (1, 3, 7, 14, 30, 60, 120)`：`stage` 是**下一轮**间隔的
  下标；`stage == len(阶梯)` 即毕业（`due_at` 清空，永不再排期）。
- 时间全部是 app 层注入的 **ISO8601 UTC 定长零填充字符串**（`%Y-%m-%dT%H:%M:%SZ`）。
  定长格式 ⇒ **字典序即时间序**，core 层不做任何时间解析即可比较到期
  （`due_at <= now`），维持「core 零 time/datetime」的既有不变式。
- 容错读（与生词本同构）：损坏先备份 `*.corrupt-*` 再空集合启动；逐条非法跳过；
  v2 字段非法值回落缺省（stage 越界/非 int → 0，review_count 负数/bool → 0）。
- **v1 → v2 迁移**（app 层 `_migrate_mastered_review`，启动时执行，幂等）：
  旧记录缺 SRS 字段 ⇒ 视为 stage=0、未排期，就地补 `due = 现在 + 1 天`——
  升级后的首个自然日起，存量已掌握词陆续进入复习，不会瞬间轰炸。

与生词词库的关系：两个词库按**互斥语义**区分管理——一个词不在生词本就在掌握库
（标记掌握时自动移出生词本；复习遗忘时自动退回生词本）。`vocab.json` 结构不变
（它是"待重学队列"，不携带 SRS 状态）。

## 二、与既有系统的对接方式

复习复用单词学习闭环的**全部既有挂点**，不新开窗口体系、不新开定时器：

```
帧循环 _on_frame_tick（既有，不新开 QTimer）
  ① 超时检测：reviewing ? _postpone_review（顺延 1h，无痕）: _dispose_word(未处理)
  ② _maybe_wake_for_review：墙钟越过最早 due → 把 _next_word_ts 提前到本帧
  ③ _show_word_bubble：守卫（单飞/气泡开/非睡觉/最小间隔）后
       → 有到期复习 ? _begin_review(due[0])   【复习优先，不受每日配额】
       → 否则按既有逻辑抽新词（排除集 = 已掌握 ∪ 当日已展示 ∪ 手动去重）
处置：
  _dispose_review(ok)  ← BubbleButtonBar 复习模式（还记得/忘了）
  _dispose_word(三态)  ← 既有新词路径，未动语义
```

对接点清单：

| 既有组件 | 对接方式 |
| --- | --- |
| `BubbleWindow.show_word` | 增加可选参 `review=True`：翻译行置空（`_word_layout` 天然跳过空行）、释义行放作答提示语；双击查详情通道复用 |
| `BubbleButtonBar.show_bar` | 增加可选参 `review=True`：同几何同 QSS，仅换文案（还记得/忘了）与信号路由（`review_ok_clicked`/`review_lapsed_clicked`） |
| 单飞槽 `_current_word` | 复习与新词**共用**同一单飞槽（互斥天然成立），`_reviewing` 区分处置路径 |
| 每日记录 `daily_log.json` | 新增两态 `review_ok` / `review_lapsed`（进 `DAILY_LOG_STATUSES`，学习记录窗口自动出筛选项与统计） |
| `WeightedWordPicker` 排除集 | 无改动：到期复习词本就在 `mastered.ids()` 排除集里，不会被新词路径抽中；遗忘退回生词本后获 `JP_VOCAB_WEIGHT` 加权 |
| 墙钟 | controller 注入 `_wall_now`（默认 `time.time`）：`due_at` 是日历时刻，睡眠/休眠唤醒后依然正确；帧循环只做浮点比较，测试可注入替身（规避虚拟时钟陷阱） |

时钟纪律：core 层（`mastered_store`）零时间解析；所有日期算术（`_iso_shift`）、
ISO→墙钟（`_iso_to_wall`）都在 app/controller 层完成。

## 三、复习调度逻辑

**排期链**：掌握瞬间 → `due = 掌握时刻 + INTERVALS[0]`；每轮「还记得」→
`stage += 1`，`due = 本轮复习时刻 + INTERVALS[stage]`；走完第 7 轮 → 毕业
（`stage = 7`、`due = ""`、不再排期）。任意一轮「忘了」→ 记录整体移出掌握库，
词回生词本，SRS 状态清零重学。

累计时间线（从掌握起算）：第 1 天 → 第 4 天 → 第 11 天 → 第 25 天 → 第 55 天 →
第 115 天 → 第 235 天毕业。共 7 轮复习。

**触发机制**（三层，全部挂在既有帧循环）：

1. **唤醒**：mastered 集合每次变化（掌握/复习/顺延/退回/清空）都重估
   `_next_review_wall_ts`（最早未毕业 due 的墙钟秒）；帧循环发现墙钟越过它且
   当前无展示词 → 把单词排期拉到本帧。
2. **优先**：单词槽到点后，`_show_word_bubble` 先查 `due_items(now_iso)`
   （按 due 升序，最早到期的先复习），有则弹复习卡片；没有才走新词抽取。
   候选池耗尽（`_pool_exhausted`）不影响复习——新词排期置 `inf` 后唤醒仍可拉起。
3. **守卫复用**：复习展示同样受单飞、气泡开关、睡觉、`BUBBLE_MIN_GAP_S` 约束；
   被挡住时由既有排期器稍后重试，不丢复习（due 只会越积越多，最终必然弹出）。

**节奏门控与每日上限**（2026-10-01 用户反馈「复习连续不断、一次量太大」后追加）：

- **节奏门控 `_next_review_ts`**：每次复习处置（作答 / 顺延）后重排为
  `now + JP_WORD_MIN..MAX_INTERVAL_S`（与生词同款 30~600s 随机节奏）。唤醒器与
  复习分支都受它约束——处置后强制等一拍，期间单词槽让位给新词；到点后若仍有
  到期复习则优先弹出。效果：复习**至多每 30~600s 一条**，与生词节奏一致，
  杜绝连环轰炸。
- **每日复习上限 `jp_review_daily_limit`**（默认 20，托盘「复习上限」档位
  10/20/30/50）：只数**已作答**的复习（`DailyLogStore.review_count_for` = 记得 +
  忘了；超时顺延不计数——没作答就没消耗注意力）。达上限后当日不再自动弹复习，
  一次性通知「今日复习任务完成」（跨日复位）；剩余到期词顺延到明天，间隔阶梯
  语义不变（晚一天复习不影响阶段的既有间隔）。托盘档位调大时复位通知标志，
  当日可继续；**手动「立即复习」不受上限约束**（显式意图，与手动新词同口径）。

**边界行为**：

| 情形 | 处置 |
| --- | --- |
| 复习泡泡超时（两按钮都没点） | 无痕顺延 +1h：不算遗忘、不推进阶段、不写日志（用户可能只是离开）；同样触发节奏门控（其余到期词不得立刻顶上） |
| 当日作答数达复习上限 | 一次性通知后今日不再自动弹；剩余到期词明天继续（阶梯间隔语义不变）；手动「立即复习」不受限 |
| 复习中用户离开数小时 | 同上，每 30s 展示超时顺延一轮，不会连环轰炸 |
| 复习期间双击气泡 | 打开详情（偷看答案），不打断复习；作答仍由按钮条完成 |
| 详情窗「记住了」点在当前复习词上 | 兜底路由为复习通过（`_on_review_ok`） |
| 「立即显示一个新单词」 | manual=True 明确要新词，到期复习不抢位 |
| 已掌握词库窗口点「立即复习」 | 让位当前词（复习词顺延/新词落未处理）后直接弹该词，跳过最小间隔（显式点击） |
| 升级首次启动 | 迁移补排期：存量掌握词从明日起陆续进入复习 |

**容量上界**：每词每天至多占 1 个单词槽（超时顺延 1h 起步）；到期复习清空后
排期自动回到新词节奏，无需限额配置。

**配额口径**：复习处置写入每日记录留痕，但**不占新词配额**——`_jp_stop_for_today`
用 `DailyLogStore.new_word_count_for`（排除 `review_ok` / `review_lapsed` 两态），
「每日数量」只由新词展示驱动；否则复习多的日子会挤掉新词学习。

## 四、用户查看与管理（已掌握词库窗口）

托盘「日语学习」新增 **「已掌握词库…」**（生词本… 与 学习记录… 之间），与生词本
窗口同构（卡片化、主题点缀色、减少动效、关闭淡出），单例重开前置。

- **顶部**：等级 Tab（全部/N5..N1，本地过滤）+ 三个操作——
  「立即复习」（选中词直接弹复习泡泡）、「退回生词本」（手动标记遗忘：移出
  掌握库 + 加入生词本 + SRS 清零）、「清空…」（二次确认后全部回到学习池）。
- **卡片**：行1 单词｜假名 + 喇叭（发音复用 `PronunciationController`）；
  行2 等级 chip + 中文翻译；行3 **记忆状态行**，例：
  - `记忆阶段 2/7 · 3 天后复习`（次级灰）
  - `记忆阶段 1/7 · 待复习（已过 2 天）`（琥珀 warning——该复习了）
  - `已毕业 · 长期记忆 · 已复习 7 次`（信息绿 info）
- **排序**：待复习的词按到期升序（最该复习的在最上，未排期瞬态置顶），
  已毕业的垫底（新毕业在前）。
- **状态栏**：`共 N 个词 · 待复习 M 个`。
- **交互**：单击选中（高亮 + 启用操作按钮）、双击开详情、喇叭点读；数据变化
  （复习通过/遗忘/退回/清空）时已打开的窗口即时刷新。
