### 原始需求复述

> 为应用的交互环节增加日语教学功能。在"吐泡泡"对话过程中，随机展示日语单词，每个泡泡内需包含日语单词、假名读音、翻译及中文释义。支持难度调节，可按 JLPT 等级（如 N1、N2、N3 等）切换或配置，以控制单词的难度范围。提供"记住了"等操作，可将选中的单词加入生词本，并支持对生词本进行查看与管理。

### 已确认的三个方向（不再回头）

1. **词库来源**：内置精选词库，随程序打包一份 JSON，JLPT **N5~N1 每级约 100 词**（共约 500 词）。离线可用、零外部依赖、体积约 100KB。
2. **「记住了」入口**：走**托盘菜单**。泡泡维持**完全不可点击**的现状（这是现有架构的刻意设计），不改成可点击。
3. **展现方式**：托盘加一个可勾选的**「日语学习」开关**。开启后泡泡优先弹日语单词；关闭后完全不影响现有情绪气泡行为，可一键回退。

## 1. 产品目标

为**正在学日语 / 备考 JLPT 的桌面宠物用户**，在既有的"陪你敲键盘 → 吐泡泡"陪伴场景里，以**低打扰、可随时关闭**的方式随机呈现分级日语单词，并提供一键「记住了」把词沉淀进生词本、以及生词本的查看与管理，解决"背单词枯燥、学习工具与陪伴场景割裂、学一会儿就想不起来"的问题；同时它是一个**纯可选开关**，对只想被陪伴的用户做到零影响、可一键回退。

## 4. UI 设计稿描述（文字 + ASCII，无需图片）

### 4.1 日语单词泡泡 —— 排版层级（核心改动）

现状：气泡只画**一段纯文本、单一字号（12pt）、整块居中**（`BubbleWindow.paintEvent` + `drawText(AlignCenter|TextWordWrap)`）。
本次改为**四行、四档字号、居中对齐**的竖排文本块：

- **字号建议（绝对值 / 相对基准 12pt 的比例）**
  - ① 日语单词：**16pt 加粗**（比例 ≈ 1.33）—— 视觉主体
  - ② 假名读音：**12pt**（比例 1.00）—— 次主体，颜色次一级
  - ③ 翻译：**11pt**（比例 ≈ 0.92）—— 常规
  - ④ 中文释义：**9pt**（比例 ≈ 0.75）—— 最淡、可换行
  - 行距：新增 `BUBBLE_LINE_SPACING`（建议 3px）
- **对齐**：四行全部**水平居中**；整个文本块在气泡 body 内**垂直居中**。
- **宽度**：学习泡泡建议加宽，新增 `JP_BUBBLE_MAX_WIDTH`（建议 **240px**，现有 `BUBBLE_MAX_WIDTH=200` 对四行偏窄）。
- **配色（新增常量，不硬编码）**：单词用主色（可沿用 `bubble_text`/`ink`）；假名、释义各用一档更淡的色（新增 `bubble_sub_text` / `bubble_faint_text`）形成层级。
- **绘制方式**：不改变"圆角矩形 + 小三角尖"外形与淡入/停留/淡出时序；新增一条**多行渲染路径**（逐行用各自字号绘制），保留原 `show_message(text)` 供情绪气泡使用（**零回归**）。

```
        ┌──────────────────────────────┐
        │            私                │   ← ① 单词 16pt 加粗 居中
        │          わたし              │   ← ② 假名 12pt 居中（次色）
        │            我                │   ← ③ 翻译 11pt 居中
        │     第一人称代词，通用说法    │   ← ④ 释义 9pt 居中（最淡）
        └───────────┬──────────────────┘
                    ▼                   ← 指向宠物头顶（现有小三角尖）
```

## 5. 数据模型草案

### 5.1 内置词库（只读，随包分发）

建议路径 `src/desktop_pet/data/jlpt_words.json`（打包进产物，见约束）。

```json
{
  "version": 1,
  "words": [
    {
      "id": "n5-0001",
      "level": "N5",
      "word": "私",
      "kana": "わたし",
      "romaji": "watashi",
      "translation": "我",
      "meaning": "第一人称代词，通用/正式说法"
    }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | string | ✅ | **全局唯一**（如 `n5-0001`），去重键 |
| level | string | ✅ | `N5 / N4 / N3 / N2 / N1` |
| word | string | ✅ | 日语单词（表记） |
| kana | string | ✅ | 假名读音 |
| romaji | string | ⬜ | 罗马音（P2，可选） |
| translation | string | ✅ | 中文翻译（简短） |
| meaning | string | ✅ | 中文释义（词性/用法/说明） |

### 5.2 生词本记录（可写，用户数据）

建议存 `%APPDATA%\desktop-pet\vocabulary.json`（独立文件，理由见 §6）。

```json
{
  "version": 1,
  "items": [
    {
      "id": "n5-0001",
      "word": "私",
      "kana": "わたし",
      "translation": "我",
      "meaning": "第一人称代词，通用/正式说法",
      "level": "N5",
      "added_at": "2025-01-01T10:00:00Z"
    }
  ]
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | **去重键**；已存在则幂等（不重复添加） |
| word / kana / translation / meaning | string | 冗余快照，便于**离线展示**且不依赖词库版本 |
| level | string | 等级标签（列表显示 + 筛选） |
| added_at | string(ISO8601) | 加入时间，**默认排序字段**（倒序） |

## 6. 约束（硬性，不可违反）

- **分层约束**：`core/` 下任何文件**禁止 import** `PySide6 / QtGui / QtWidgets / QtCore`（有静态测试守护）。词库加载、难度/抽取逻辑、生词本存储**必须落在 `core/`**；窗口与绘制在 `ui/`。
- **零外部图片素材**：仍须纯 QPainter 矢量绘制（有测试扫 `.png/.jpg`）。**注意：JSON 文本词库不受此限**。
- **画布尺寸**：`BASE_W=160` / `BASE_H=180` **不可改**（有测试硬断言）。
- **禁止 `print`**：统一 `logger = logging.getLogger(__name__)`。
- **常量唯一来源**：所有新增阈值 / 配色 / 尺寸 / 文案**只允许新增在 `core/constants.py`**，其它模块只能引用（见 §7）。
- **不改动泡泡交互模型**：泡泡维持 `WindowTransparentForInput` + 鼠标事件透传的**零交互**现状，**不得**改成可点击。
- **打包**：新增的 JSON 词库文件必须纳入打包配置（PyInstaller `datas` / wheel package-data），并保证冻结环境下可定位。

### 不得退化的既有能力（回归红线）

- 双手敲键盘动画与击键幅度：**落指 10px / 抬腕 13.5px / 键帽下沉 4px**；
- **8 种表情**仍可区分；
- 脏矩形渲染不裁剪；
- 无边框窗口拖拽与点击的 **5px 阈值**区分；
- 开机自启、缩放档位 **0.8 / 1.0 / 1.2**；
- 现有 **286 个自动化测试**保持全绿。

### 建议新增的常量（集中放 `core/constants.py`）

- 等级：`JP_LEVELS`（N5..N1 有序元组）、`JP_DEFAULT_LEVEL`；
- 节奏：`JP_WORD_MIN_INTERVAL_S` / `JP_WORD_MAX_INTERVAL_S`；
- 排版：`JP_BUBBLE_WORD_FONT_SIZE` / `JP_BUBBLE_KANA_FONT_SIZE` / `JP_BUBBLE_TRANSLATION_FONT_SIZE` / `JP_BUBBLE_MEANING_FONT_SIZE` / `JP_BUBBLE_MAX_WIDTH` / `BUBBLE_LINE_SPACING`；
- 配色：`COLORS` 中新增 假名/释义 次级文字色、生词本窗口底色/文字色、等级标签色；
- 文件与文案：`VOCAB_FILE_NAME`、词库文件名、生词本空态文案、托盘通知文案。

## 7. 待确认问题（需用户拍板）

> 每条给出**两个选项**与**我的推荐**。默认按推荐执行。

1. **难度档位模型：单等级 vs 范围**
   - A（推荐）：**单选一个等级**（N5/N4/N3/N2/N1），抽取范围就是该等级。
   - B：支持范围（如「N5–N3 混合」）。
   - **推荐 A**：① 与现有「大小」子菜单的互斥单选范式一致，零新交互成本；② 每级约 100 词 + JP-07 洗牌去重，已足够避免重复，无需靠范围扩池；③ 范围会让"当前在学哪一档"变得模糊。范围可作为 P2。

2. **「日语学习」开关与「气泡提示」总开关的关系**
   - A（推荐）：**AND 逻辑**——气泡总开关为关时，即使开了日语学习也不弹单词；开启日语学习而气泡总开关为关时，给一次托盘通知提示先开气泡。
   - B：开启日语学习时**自动打开**气泡总开关。
   - **推荐 A**：尊重用户对总开关的显式意图，不偷偷改用户设置；对"开了却没反应"的困惑用通知消解。

3. **单词出现的触发方式**
   - A（推荐）：**独立低频节奏**（在帧循环里像"随机打呵欠"那样用独立定时器，随机间隔 25~50s 触发）。
   - B：复用情绪切换时机"顺便弹单词"。
   - **推荐 A**：情绪切换**稀疏且不可控**，无法保证学习节奏；独立定时器可复用现有 `_on_frame_tick` + `motion.random_interval` 模式，改动面小、节奏稳定。

4. **生词本的存储形态**
   - A（推荐）：**单独文件** `vocabulary.json`。
   - B：并入 `config.json`。
   - **推荐 A**：① 配置是"设置"（小、频繁写、逐字段容错回落），生词本是"用户数据"（追加式、绝不能被回落逻辑清空）；② 混存会导致每次改配置都要序列化整本生词本；③ 版本演进互不耦合。实现上可抽出与 `ConfigStore` 同构的 `VocabularyStore`。

5. **生词本窗口的形态**
   - A（推荐）：**独立非模态窗口**（列表 + 筛选 + 按钮）。
   - B：托盘菜单里动态生成词条子菜单。
   - **推荐 A**：菜单不适合展示四列字段与批量操作；独立窗口是标准做法，也便于后续加筛选/导出。

6. **睡觉态是否弹单词？**
   - A（推荐）：**不弹**（`Mood.SLEEP` 期间跳过），醒来后照常。
   - B：照常弹。
   - **推荐 A**：与宠物"睡着"的视觉语义一致，也降低打扰。
