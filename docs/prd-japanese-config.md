## 5. 关键业务规则（重点）

### 规则 1：显示时长三选枚举

- **档位**（互斥单选）：`15s / 30s / 60s`；**默认 30s**。
- 持久化到 `config.json` 的 `jp_bubble_duration_s`（改为 int 秒）。
- **旧值兼容**：旧配置若为 `15/30/60` 之一 → 直接沿用；否则（如 45 / 2 / 300）→ **回落默认 30s**（`_coerce_duration` 由「连续钳制」改为「档位集合收敛」）。
- **超时 → 未处理**：沿用 JM-02，语义与三态状态机**完全不变**，不重复定义。

### 规则 2：每日数量选择菜单

- **档位**（互斥单选）：建议 `5 / 10 / 15 / 20 / 30`；**默认 15**（具体集合见 §8 Q2，可调）。
- 持久化到 `config.json` 的 `jp_daily_limit`（int）。
- **旧值兼容**：旧配置若命中档位 → 沿用；否则回落默认 15。
- **全掌握提前停 / 跨日重置**：沿用 JM-07 / JM-11，语义不变（`当日 mastered 数 == shown_today 数 > 0` 即提前停；本地自然日 00:00 归零计数与当日已显示集合；已掌握/生词本不随日重置）。

### 规则 3：「立即显示」与上限 / 超时的交互

- **触发**：托盘「立即显示一个新单词」→ controller 立即执行一次「抽取 + 展示」，**绕过**随机 25~50s 排期与 `BUBBLE_MIN_GAP_S`。
- **守卫**（与随机节奏共享停止条件，满足其一则**不展示**并给通知）：
  1. `shown_today ≥ jp_daily_limit`（每日上限）→ 通知「今日学习完成」；
  2. 当日全部已展示词均已掌握（全掌握提前停）→ 同上；
  3. 睡觉态（`Mood.SLEEP`）→ 不弹（待醒来）；
  4. 气泡总开关关闭 / 词库为空 / 该等级已被已掌握排空 → 对应降级通知。
- **与当前展示词的关系（推荐 A）**：若当前有词正在展示，**先按「未处理」处置当前词（等价超时）**，再立即展示新词；`shown_today` 因此 +1。这样「立即」语义始终成立，且复用 `_dispose_word(UNPROCESSED)` + `_show_word_bubble` 单飞路径，不引入新竞态。（备选 B 见 §8 Q3）
- **展示后**：进入标准单飞状态（`deadline = now + 显示时长`），「记住了 / 新单词」按钮与超时处置逻辑**不变**。
- **抽取规则不变**：排除已掌握 + 当日不重复 + 生词加权（`JP_VOCAB_WEIGHT=3.0`）。

### 规则 4：双击详情窗口数据流与降级

- **触发**：学习记录窗口表格行**双击**（P0）；生词本窗口双击（P1，JC-09）。
- **打开**：非模态详情窗口（`ui/` 新组件 `WordDetailWindow`），单例、重开前置。
- **数据流（关键顺序）**：
  1. controller 收到 `(source, id)` → 用词条 `id` 从 `WordBank` 解析出完整 `VocabEntry`（含 `meaning`/`romaji`）作为**本地兜底**；
  2. 详情窗口**立即渲染本地字段**（word / kana / translation / meaning / level / romaji），**零网络等待**；
  3. **异步**发起 Jisho 查询（后台线程，标准库 `urllib.request` + `json`，超时约 5s，不引入 requests）；
  4. 结果回主线程，三态：
     - **加载中**：详情区顶部显示「正在查询 Jisho 词典…」（本地字段已可见，不阻塞交互）；
     - **成功**：填充联网字段——读音 `reading`、词性 `parts_of_speech`、英文释义 `english_definitions`、`jlpt` 标签、`is_common`（标注「常见」），并标注来源「Jisho」；
     - **失败 / 超时 / 断网**：**保留本地字段**，显示降级提示「联网查询失败，已显示本地词条」+ 可选「重试」（JC-08）。
- **缓存**：会话内**内存缓存**（二次双击秒开、不重复请求，P0）；持久化 `jisho_cache.json` + TTL（P1，JC-08）。
- **分层与零依赖**：
  - `core/jisho.py` 负责「URL 构造 + 请求 + JSON 解析」→ 返回 `JishoResult` dataclass；**禁止 import Qt、禁止 import time/datetime**（core 时钟无关约定，`fetched_at` 由 app 注入）；
  - `ui/` 用 `QThreadPool`/`QRunnable` 跑后台请求，用 `Signal` 把结果/错误回主线程；**不在 core 开线程**。
- **语言说明**：Jisho 返回**英文**释义；中文释义来自本地字段，两者**并存展示**，不做机器翻译。
- **限流礼仪**：仅用户主动双击才联网、结果缓存、不自动批量抓取。

### 规则 5：删除旧菜单项「加入生词本」的功能等价性

- **旧功能**：托盘「加入生词本」（前身「记住当前单词」）= 把**当前展示词**标记为「生词」（`_dispose_word(VOCAB)`）。
- **等价承接**：气泡「**新单词**」按钮走**同一条** `_dispose_word(VOCAB)` 处置路径，能力**完整保留、不丢失**。
- **删除范围**：托盘菜单项、对应 `Signal(jp_add_vocab_requested)`、controller 槽 `_on_jp_add_vocab`、`set_jp_current_word` 动态文案逻辑（不再需要即可清理）；`jp_add_vocab` 相关常量（`JP_MENU_ADD_VOCAB*`）一并移除或保留为空档。
- **菜单落位**：新「立即显示一个新单词」插入日语菜单组（「难度」之后、「生词本…」之前），取代原「加入生词本」位置，不动其它项顺序。
- **置灰策略**：关闭「日语学习」时，「难度 / 显示时长 / 每日数量 / 立即显示」置灰；「生词本… / 学习记录…」始终可用（沿用 JM 置灰范式）。
- **说明**：这是对记忆 PRD §6.3 / 待确认 Q2 的进一步收敛——最终结论是「加入生词本」菜单项**删除**，只保留气泡「新单词」按钮 + 新增「立即显示」。

### 6.2 Jisho 查询结果（新建 `core/jisho.py`，只读）

```python
@dataclass(frozen=True)
class JishoResult:
    word: str            # 查询词（冗余）
    readings: tuple[str, ...]        # 读音（reading）
    parts_of_speech: tuple[str, ...] # 词性
    english_definitions: tuple[str, ...]  # 英文释义（取前 N 条）
    jlpt: tuple[str, ...]            # Jisho 返回的 JLPT 标签
    is_common: bool                  # 常见度
```

- 解析函数：`fetch(keyword: str, timeout_s: float) -> JishoResult`，用 `urllib.request.urlopen(timeout=...)` + `json.loads`；任何网络/解析异常 → 抛出可被上层捕获的 `JishoError`（不 import Qt）。
- 端点：`https://jisho.org/api/v1/search/words?keyword=<urlencoded 词条>`，取 `data[0]`；无结果 → 空 `JishoResult` 或 `JishoNotFound`。

### 6.3 Jisho 缓存（新建 `core/jisho_cache_store.py`，P1，JC-08）

建议路径 `%APPDATA%\desktop-pet\jisho_cache.json`：

```json
{
  "version": 1,
  "items": {
    "私": { "fetched_at": "2025-01-01T10:00:00Z",
            "result": { "readings": ["わたし"], "parts_of_speech": ["Pronoun"],
                        "english_definitions": ["I", "me"], "jlpt": ["jlpt-n5"], "is_common": true } }
  }
}
```

- 复用 `VocabStore` 同构「原子写 + 逐字段容错 + 损坏备份」范式；`fetched_at` 由 app 注入（core 不取时钟）。
- TTL 判定在 app 层（对比 `fetched_at` 与当前时间）；缓存只读查询、按需覆盖。

- **即时渲染**：本地字段（word/kana/translation/meaning/level/romaji）在窗口打开瞬间就显示，联网区异步填充，**绝不因网络卡住窗口**。
- 三态在「联网区」内切换，不影响上方本地字段。
- 建议初始尺寸约 **420 × 420**，可缩放；单例、重开前置。

### 7.3 气泡质感重构（JC-07，纯 QPainter 矢量，零外部图片）

在既有「四行多字号 + 顶部高光」基础上：

- **body 渐变**：顶部高光（已有 `bubble_gradient_hi`）扩展为「顶部高光 → 中部奶白 → 底部略深」的垂直渐变，避免纯平底。
- **底部柔和阴影**：气泡 body 下方加一层极淡的阴影（多层半透明圆角矩形错位绘制近似模糊），增强浮起感。
- **分组分割线**：在「单词/假名」与「翻译/释义」两组之间画一条细分割线（新增 `bubble_divider` 色）。
- **等级角标**：气泡 body 右上角加一个小圆角 `N5` chip（柔和底色 + 白色小字，新增 `jp_level_chip_bg/text`）。
- **按钮条微交互**：主按钮（记住了）渐变填充、次按钮（新单词）描边，悬停高亮 + 按下轻微下沉/回弹（已有基础，打磨为渐变 + 轻投影）。
- 所有新增配色/尺寸集中 `core/constants.py`（`bubble_shadow` / `bubble_divider` / `jp_level_chip_bg` / `jp_level_chip_text` 等），不硬编码；文字区仍保持 `WindowTransparentForInput` 透传，仅按钮条可点（沿用）。

## 8. 待确认问题（不阻塞，附建议默认值）

1. **显示时长档位是否锁定 15/30/60？**
   - 推荐：**锁定三档**（需求明确）。默认 **30s**。若要更细分可后续加 10s/45s，本期不做。

2. **每日数量档位集合？**
   - 推荐：**`5 / 10 / 15 / 20 / 30`**，默认 **15**。理由：覆盖「轻量→重负荷」且整数好记；若想更宽可加 `50`。

3. **「立即显示」遇当前词在展示时的处理？**
   - A（推荐）：先按「未处理」处置当前词，再立即展示新词（「立即」语义始终成立，复用单飞路径）。
   - B：当前有词时 no-op 并通知「当前已有单词展示中」（不打断，但「立即」可能不生效）。
   - **推荐 A**。

4. **Jisho 释义为英文，是否接受与本地中文并存？**
   - 推荐：**接受并存**，标注「Jisho（英文）」与「本地（中文）」，不做机器翻译。默认此口径。

5. **缓存策略（TTL / 落盘）**
   - 推荐：内存缓存 P0（会话内秒开）；**持久化 `jisho_cache.json` + TTL 7 天进 P1**，详情窗口带「重试/刷新」。默认此口径。

6. **详情窗口是否也从生词本双击打开？**
   - 推荐：学习记录双击为 P0，**生词本双击为 P1**（复用同一组件）。默认此口径。

7. **联网方式与超时**
   - 推荐：标准库 `urllib.request`，**超时 5s**，不引入 requests；仅用户主动双击触发。默认此口径。

## 9. 不做的事（Out of Scope）

- **不重写 A 版记忆闭环**：三态状态机、已掌握永久排除、每日配额、全掌握提前停、跨日重置、回查语义均不改。
- **不引入新第三方依赖**：联网用标准库 `urllib.request` + `json`，不引入 requests / httpx。
- **不做自动联网抓取 / 词库在线化**：Jisho 仅按用户主动双击查询；词库仍内置离线 JSON。
- **不做发音 / TTS / 例句大列表 / 机器翻译**。
- **不改 `BASE_W/BASE_H`**、不改击键动画 / 表情 / 拖拽 / 缩放 / 自启等既有红线（回归红线沿用 JP/JM 系列）。
- **不改气泡零交互模型**：文字区仍透传，仅按钮条可点。

## 10. 约束（沿用，硬性）

- 分层：`app → ui → core` 严格单向；`core/` 禁止 import Qt、禁止 import `time`/`datetime`；Jisho 抓取/解析落 `core/jisho.py`，线程与信号在 `ui/` 或 `app/`。
- 常量唯一来源 `core/constants.py`（新增 `JP_BUBBLE_DURATION_OPTIONS` / `JP_DAILY_LIMIT_OPTIONS` / `JP_MENU_*` / `jisho_*` 配色等）。
- 零外部图片素材：气泡/按钮/详情窗口均纯 QPainter 矢量绘制。
- 禁止 `print`，统一 `logging`。
- 新增 JSON 数据文件（`jisho_cache.json`）纳入打包配置；用户数据损坏时**备份不静默清空**，与既有 store 同范式。
- 现有自动化测试保持全绿；新增能力需配套 core 层单测（档位收敛、Jisho 解析、缓存容错）。
