### 原始需求复述

> 1. 单词气泡显示时长可配置（默认 30 秒），超时无操作自动消失；超时单词按「未处理」对待，不计入已掌握或生词。
> 2. 气泡下方提供「记住了」与「新单词」两个按钮：点击分别移入「已掌握集合」（后续不再出现）和「生词本」（后续出现概率提高），并立即关闭气泡。
> 3. 每日显示数量可配置（默认 15 个）；当日已显示单词全部标记「记住了」时，今日剩余时间不再显示任何单词。
> 4. 每日单词具备回查功能，可查询历史显示记录及标记状态（已掌握/生词/未处理）。
> 5. 气泡 UI 需有质感与设计感，视觉层次丰富，避免朴素样式。

## 5. 关键业务规则（重点）

### 规则 1：三态定义（唯一状态机）

| 状态 | 触发 | 后续行为 |
| --- | --- | --- |
| **已掌握 mastered** | 点「记住了」 | 加入已掌握集合；**永久不再出现**（抽取时按 id 排除） |
| **生词 vocab** | 点「新单词」 | 加入生词本；**出现概率提高**（加权抽取） |
| **未处理 unprocessed** | 超时未操作（或无任何标记） | 不进任何集合，仅记入每日记录；跨日后可再次出现 |

> 三态**互斥**：一次展示只会落入一种终态（点按钮立即关气泡 → 无「既掌握又生词」；超时即未处理）。

### 规则 2：已掌握永久排除

- 以词条 `id` 为键维护「已掌握集合」，**跨等级、跨日全局生效**。
- 抽取候选池 = 当前等级词库 − 已掌握 id。候选池为空时：托盘通知「该等级单词已全部掌握」，并停止今日展示。

### 规则 3：超时 = 未处理（不依赖气泡回调）

- controller 在展示某词时记录 `展示时间` 与 `deadline = now + jp_bubble_duration_s`。
- 帧循环中当 `now ≥ deadline` 且用户未点任何按钮 → 将该词落为「未处理」记录，然后按节奏排期下一词。
- 说明：气泡自身按 `duration` 淡出即可，**无需给 `BubbleWindow` 增加超时回调**；「未处理」判定统一由 controller 的定时器完成（单一事实来源，避免气泡回调和按钮点击竞态）。

### 规则 4：每日上限 + 提前停

- 每日展示计数 `shown_today`，从 0 起，每弹一词 +1（无论终态）。
- 停止条件（满足其一即今日不再弹）：
  1. `shown_today ≥ jp_daily_limit`（默认 15）；
  2. 当日已显示的单词**全部**为「已掌握」（即 `当日 mastered 数 == 当日 shown_today 数` 且 `shown_today > 0`）。
- 停止后可选托盘通知「今日学习完成 ✅」（P1 文案）。

### 规则 5：跨日重置

- 计数与「今日已显示 id 集合」按**本地时区自然日 00:00** 归零。
- 已掌握集合、生词本**不随日重置**（是全局长期数据）。
- 判定「新的一天」：对比本地日期字符串（如 `YYYY-MM-DD`）是否变化；运行期间跨日也需在帧循环检测。

### 规则 6：重复单词（当日不重复 + 已掌握永不重复）

- **已掌握**：永不重复（全局）。
- **当日已显示**：同一自然日内同一词条不二次弹出（无论其终态是未处理/生词）。
- **跨日**：未处理、生词可再次出现；生词仍享受加权。
- 说明：本规则以「当日不重复」替代/强化既有 JP-07 的「一轮内不重复」，语义更直观、且与每日记录天然一致。

### 规则 7：生词概率提高

- 抽取时先「排除已掌握 + 排除当日已显示」，再在剩余候选中按权重随机：
  - 生词本内的词：权重 `JP_VOCAB_WEIGHT`（推荐 3.0，P1 可配）；
  - 普通词：权重 1.0。
- 加权抽样与既有 `WordSampler` 洗牌队列的关系：**推荐改为加权随机 + 当日去重**，替换洗牌队列（见 §8 Q3）。若坚持保留洗牌，则以「加权放回抽样 + 当日去重过滤」实现。

## 6. UI 设计稿描述

### 6.1 学习气泡 + 按钮区（核心改动）

```
        ┌──────────────────────────────┐
        │            私                │   ← ① 单词 16pt 加粗 居中
        │          わたし              │   ← ② 假名 12pt 居中（次色）
        │            我                │   ← ③ 翻译 11pt 居中
        │     第一人称代词，通用说法    │   ← ④ 释义 9pt 居中（最淡）
        └───────────┬──────────────────┘
                    ▼                   ← 指向宠物头顶（现有小三角尖）
        ┌─────────────┬──────────────┐
        │  记住了      │   新单词     │   ← 按钮条（气泡正下方，圆角胶囊按钮）
        └─────────────┴──────────────┘
```

- **按钮条形态**：气泡正下方一个独立的**按钮条浮层**（两个圆角胶囊 `QPushButton`），与气泡同锚点、底部对齐、随气泡一起淡入/淡出。
  - 「记住了」：主色填充（强调正向）；「新单词」：描边/次级色（次要操作）。
  - 按钮文案、配色、圆角、内边距集中 `core/constants.py`（新增 `JP_BUTTON_*` 常量）。
- **质感/层次要求（对应需求点 5）**：
  - 气泡 body：沿用圆角矩形 + 小三角尖，新增**浅色渐变或更柔和的底色分层**（如顶部高光 → 底部阴影），避免纯平底色；
  - 四行文字保持 16/12/11/9pt 层级（沿用 JP-05 的多字号），并可用细分割线或留白区分「单词/假名」与「翻译/释义」两组；
  - 按钮采用**圆角胶囊 + 悬停高亮 + 按下回弹**微交互，提升质感；
  - 所有颜色取自 `C.COLORS`（新增 `bubble_*`/`jp_button_*` 键），不硬编码。
- **零交互取舍**：文字区保持 `WindowTransparentForInput` 透传现状；**仅按钮条区域可点击**（按钮条是独立可交互控件）。这样既有「点击穿透」语义在文字区不破坏，同时满足「有按钮」需求。

### 6.2 学习记录（回查）窗口

新增独立非模态窗口（`ui/` 层，范式同 `vocab_window.py`）：

│  日期：[ 2025-01-01 ▾ ]  状态：[ 全部 ▾ ]        │  ← 日期 + 状态筛选
├──────────────────────────────────────────────────┤

- 默认显示「今天」；日期下拉可回看历史（P0 至少支持日期选择，P1 加状态筛选）。
- 状态用**颜色标签**（已掌握绿 / 生词蓝 / 未处理灰）而非纯文本，提升可读性。

### 7.2 已掌握集合（新建 store）

建议路径 `%APPDATA%\desktop-pet\mastered.json`：

```json
{
  "version": 1,
  "items": [
    { "id": "n5-0001", "word": "私", "kana": "わたし",
      "translation": "我", "level": "N5", "mastered_at": "2025-01-01T10:00:00Z" }
  ]
}
```

- 复用 `VocabStore` 同构的「原子写 + 逐字段容错 + 损坏备份」范式（新建 `MasteredStore`）。
- 按 `id` 去重；字段为冗余快照（离线展示/回查用，不依赖词库版本）。

### 7.3 每日显示记录（新建 store）

建议路径 `%APPDATA%\desktop-pet\daily_log.json`：

```json
{
  "version": 1,
  "days": {
    "2025-01-01": [
      { "id": "n5-0001", "word": "私", "kana": "わたし",
        "translation": "我", "level": "N5",
        "shown_at": "2025-01-01T14:02:10Z", "status": "mastered" }
    ]
  }
}
```

- `status ∈ {mastered, vocab, unprocessed}`（三态，唯一取值）。
- 按本地日期 `YYYY-MM-DD` 分桶；回查窗口按日期读取。
- 同 store 提供「当日计数 / 当日已显示 id 集合 / 当日全部已掌握？」等查询接口（供 controller 判定停止条件）。

## 8. 待确认问题（不阻塞，附建议默认值）

1. **按钮如何打破「零交互」？（关键架构变更）**
   - A（推荐）：气泡文字区保持透传，**新增独立按钮条浮层**（仅按钮可点）。回归最小、语义清晰。
   - B：气泡窗口整体改为可点击。风险大（触碰拖拽/点击 5px 阈值与既有交互）。
   - **推荐 A**。

2. **托盘「记住当前单词」与新按钮的关系**
   - A（推荐）：托盘项**改名/对齐为「加入生词本」**（= 气泡「新单词」）；「已掌握」操作只在气泡按钮完成（可另加托盘「标记已掌握」为 P2）。
   - B：托盘「记住当前单词」= 已掌握，「新单词」仅气泡有。
   - **推荐 A**：避免「记住」二字同时指两个不同动作，语义混乱。

3. **非重复粒度：当日不重复 vs 一轮洗牌不重复**
   - A（推荐）：改为**加权随机 + 当日去重**（替换 `WordSampler` 洗牌队列）。
   - B：保留洗牌队列，仅在其上叠加「排除已掌握 + 生词加权」。
   - **推荐 A**：与每日记录天然一致、可推理；B 在「加权」与「一轮不重复」之间存在语义冲突。

4. **生词权重倍数**
   - 推荐 **3.0**（普通词 1.0）。可后续按数据调。**默认 3.0**。

5. **「全部记住则提前停」的判定口径**
   - 推荐：`当日 shown_today > 0 且 当日 mastered 数 == shown_today`。即当日至少展示过、且每一条都被标「已掌握」。**默认此口径**。

6. **每日上限是否含「未处理/生词」？**
   - 推荐：**含**——上限约束的是「展示次数」，不约束终态。**默认含**。

## 10. 约束（沿用，硬性）

- 分层：`app → ui → core` 严格单向；`core/` 禁止 import Qt；词库/抽取/记忆/记录逻辑全部落 `core/`。
- 常量唯一来源 `core/constants.py`（新增 `JP_*` / `JP_BUTTON_*` / `MASTERED_*` / `DAILY_LOG_*` 等）。
- 零外部图片素材：纯 QPainter 矢量绘制。
- 禁止 `print`，统一 `logging`。
- 新增 JSON 数据文件需纳入打包配置（`desktop-pet.spec` / `pyproject.toml`）。
- `mastered.json` / `daily_log.json` 均为**用户数据**：损坏时**备份不静默清空**，与 `vocabulary.json` 同范式。
